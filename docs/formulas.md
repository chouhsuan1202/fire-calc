# 計算公式的數學定義

這份文件列出 FIRE 計算器用到的每一條公式，對應的程式在根目錄的 `fire-core.js`，測試在 `tests/fire-core.test.js`。每一條都附上跟姊妹專案 withdraw-calc（提領計算機）的對照。

## 符號

| 符號 | 意思 | 單位 |
| --- | --- | --- |
| M | 退休後每月支出 | 金額（內部一律 EUR） |
| k | 倍數，15、17、25、33 | 倍 |
| T | 目標金額 | 金額 |
| V0 | 起始資產 = 現有投資資產 + 一次投入 | 金額 |
| Vn | 第 n 年年底的資產 | 金額 |
| A | 每年再投入 | 金額／年 |
| r | 底層報酬率 | 年化小數，8% 寫 0.08 |
| L | 槓桿倍數，1.0 到 2.0 | 倍 |
| i | 借款利率 | 年化小數 |
| g | 有效報酬率（槓桿後） | 年化小數 |
| π | 通膨率 | 年化小數 |
| N | 年數上限，60 | 年 |

## 1. 目標金額與提領率

```
T = M 乘以 12 乘以 k
起始提領率 w = 12 M ÷ T = 1 ÷ k
```

| k | w = 1 ÷ k | 出處 |
| --- | --- | --- |
| 15 | 6.67% | CLEC 最低門檻 |
| 17 | 5.88% | 清流君動態提領，全股票約 6% 起始（1 ÷ 6% = 16.7，取 17） |
| 25 | 4.00% | 4% 法則 |
| 33 | 3.03% | CLEC 保守版，提 3% |

程式：`targetAmount(M, k)`。

驗證：正確。手算 4,000 乘以 12 乘以 25 = 1,200,000。

對照 withdraw-calc：它反過來算「每月想領 M 要多少本金」，`requiredPrincipal` 的公式是 `(12 M + 一年利息) ÷ 門檻`。借款為 0 時就是 `12 M ÷ w`，跟這裡的 `T = 12 M 乘以 (1 ÷ w)` 是同一條式子。兩邊的提領率都以「起始本金」為分母、都是一年的金額除以本金，定義一致。差別在門檻數字的來源（見文末「兩邊的模型差異」）。

## 2. 有效報酬（槓桿）

```
g = r + (L 減 1) 乘以 (r 減 i)
  = L 乘以 r 減 (L 減 1) 乘以 i
```

推導：自有資金 1 元，再借 (L 減 1) 元，一共投入 L 元。一年後賺 L 乘以 r，付利息 (L 減 1) 乘以 i，自有資金的報酬就是上式。假設每年再平衡維持固定槓桿，不計波動耗損。

程式：`effectiveReturn(r, L, i)`。

驗證：正確。手算 8% 底層、1.5 倍、4% 借款：0.08 + 0.5 乘以 0.04 = 0.10。

對照 withdraw-calc：它的一年利息是 `借款 乘以 年利率`（`annualInterest`），每月是再除以 12，都是單利、一年結算一次。這裡的 (L 減 1) 乘以 i 是同一種算法，一致。

## 3. 複利滾存與年數

```
V0 = 現有投資資產 + 一次投入
Vn = max(0, Vn減1 乘以 (1 + g)) + A
年數 n* = 最小的 n（0 到 N），使 Vn >= T；N 年內都沒有就是「60 年以上」
```

* 每年先用 g 複利滾一年，**年底**才投入 A（期末年金）。
* `max(0, ...)`：g 低於負 100% 時資產最多歸零，不會變成負數。
* 判斷 Vn >= T 時容許 T 的十億分之一誤差，避免浮點誤差讓剛好達標的那年被漏掉。
* 已經達標（V0 >= T）就是 0 年。

當 g 不是 0、而且沒有觸發歸零時，有封閉解（等比級數）：

```
Vn = V0 乘以 (1 + g)^n + A 乘以 ((1 + g)^n 減 1) ÷ g
g = 0 時：Vn = V0 + n 乘以 A
g > 0 時：n* = 無條件進位( ln((T + A ÷ g) ÷ (V0 + A ÷ g)) ÷ ln(1 + g) )
```

程式：`stepYear`、`yearsToTarget`、`projectYears`（逐年資產表）。`tests/reference.py` 用精確分數逐年算一次、再用封閉解算一次，500 組案例三邊一致。

驗證：正確。手算預設值（20 萬、每年 1 萬、8%）：第 1 年 200,000 乘以 1.08 + 10,000 = 226,000，第 2 年 226,000 乘以 1.08 + 10,000 = 254,080。

對照 withdraw-calc：它的計算機本身沒有「幾年到」，但回測 `backtest/backtest.py` 也是逐期複利：`部位 乘以 (本月價格 ÷ 上月價格)`，再扣利息與提領。方向相反（一邊存、一邊領），複利的寫法一致。

## 4. 敏感度（以 25 倍為準）

| 情境 | 改了什麼 |
| --- | --- |
| 退休後每月支出少 20% | T 改成 0.8 M 乘以 12 乘以 25 |
| 底層報酬多 2 個百分點 | r 改成 r + 0.02，再代入公式 2（槓桿也會放大這 2 個百分點） |
| 每年再投入多 5,000 | A 改成 A + 5,000（以畫面幣別計，換回 EUR 再算） |

程式：`sensitivity`。驗證：正確，預設值四個情境是 19、16、16、17 年，由 Python 精確計算確認。

## 5. 通膨

計算器裡的報酬一律是**名目**報酬，退休後每月支出是**今天的錢**。要讓兩邊用同一種錢，正確做法是把報酬換成實質報酬（費雪方程式）：

```
實質報酬 = (1 + 名目報酬) ÷ (1 + π) 減 1
```

有槓桿時，底層報酬與借款利率都用同一條式子換算，結果剛好等於把名目有效報酬整個換算：

```
r' = (1 + r) ÷ (1 + π) 減 1，i' = (1 + i) ÷ (1 + π) 減 1
r' + (L 減 1) 乘以 (r' 減 i') = (1 + g) ÷ (1 + π) 減 1
```

驗證：**原本的說明有誤差，已修正**。頁面原本寫「每個報酬率再減 2% 左右」，也就是 r 減 π。這是近似值，π 是 2% 時 8% 會被算成 6%，精確值是 5.88%。這 0.12 個百分點在預設值的 17 倍目標上差一年（6% 是 17 年，5.88% 是 18 年）。現在頁面與 README 改成上面的精確公式。

對照 withdraw-calc：它也沒有通膨欄位，回測的固定提領金額是名目固定，沒有每年隨通膨調高。

## 6. 幣別

```
TWD 金額 = EUR 金額 乘以 匯率
EUR 金額 = TWD 金額 ÷ 匯率
```

內部一律以 EUR 記帳。在 TWD 模式改匯率時，每個金額乘以 舊匯率 ÷ 新匯率，讓畫面上的台幣數字不變。

程式：`toDisplay`、`toOther`、`fromDisplay`。驗證：正確。withdraw-calc 只有新台幣（單位萬），沒有對應公式。

## 7. 顯示的四捨五入

```
金額：四捨五入到整數，加千分位
百分比：先只保留 12 位有效數字去掉浮點雜訊，再四捨五入到小數一位
```

驗證：**百分比原本有錯，已修正**。6% 底層、1.5 倍、1.5% 借款，有效報酬數學上是 0.06 + 0.5 乘以 0.045 = 8.25%，四捨五入應該顯示 8.3%。但浮點數算出 0.08249999999999999，原本直接四捨五入就變成 8.2%。現在跟 withdraw-calc 的 `pct()` 一樣先用 `clean()` 去掉雜訊。

金額沒有套用 `clean()`：金額上限是 10 兆（14 位數），只留 12 位會把尾數變成 0。實測常見輸入沒有找到金額被浮點誤差捨錯的情況。

## 8. 輸入範圍

| 欄位 | 範圍 | 空白時 |
| --- | --- | --- |
| 匯率 | 大於 0，最高 100,000 | 錯誤 |
| 現有投資資產、一次投入 | 0 到 10 兆 | 當 0 |
| 現在、退休後每月支出 | 大於 0，最高 1,000 億 | 錯誤 |
| 每年再投入 | 0 到 1 兆 | 當 0 |
| 底層報酬率 | 負 50% 到 50% | 錯誤 |
| 借款利率 | 0% 到 30% | 錯誤 |
| 槓桿 | 1.0 到 2.0，每格 0.1 | 滑桿不會空白 |

有錯的欄位會標紅並顯示原因，結果先用上一次的有效數字計算，畫面不會出現 NaN 或 Infinity。

## 兩邊的模型差異（沒有改，供作者判斷）

這些不是算錯，是兩個工具的假設不同，放在這裡讓兩邊對得起來：

1. **門檻的來源不同。** fire-calc 的 15 到 33 倍來自老師們的說法（4% 法則是 30 年、提領金額隨通膨調整）。withdraw-calc 的 6.4%、7.6%、6.8%、8.8% 是用 0050 與加權指數回測 5、10、15 年得到，而且固定提領金額不隨通膨調整。換成倍數，withdraw-calc 的「最穩」6.4% 約 15.6 倍，「上限」7.6% 約 13.2 倍，比 fire-calc 最低的 15 倍還寬鬆。
2. **借款在退休後的處理不同。** withdraw-calc 把借款利息算進每年流出（領的錢加利息，再除以本金）。fire-calc 的目標金額 T 只看生活費，沒有扣退休後還在付的利息，等於假設退休前已經把槓桿降回 1 倍。如果退休後還維持槓桿，用 withdraw-calc 的定義，目標應該是 `12 M ÷ (w 減 (L 減 1) 乘以 i)`。
3. **借款的意思不同。** fire-calc 的借款是拿來加碼投資（槓桿倍數）。withdraw-calc 的借款只繳息、不進股票帳戶（回測裡是房貸之類的負債）。
